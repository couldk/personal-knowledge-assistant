# 需求说明

## 问题陈述

用户需要通过对话方式检索个人技术文档，同时保证信息来源可追溯，并避免不同用户之间发生记忆泄漏。

## 核心用户故事

- 作为用户，我可以导入 Markdown、PDF 和纯文本文件。
- 我可以提出问题，并获得包含文档和片段引用的回答。
- 当现有证据不足时，系统会明确告知我。
- 我可以延续对话，而不必在每次请求中重新发送全部历史消息。
- 我可以保存、查看、更正和删除个人偏好。
- 作为运维人员，我可以追踪检索、模型调用和工具活动。

## 功能需求

1. 文档导入支持增量处理，并通过内容哈希去重。
2. 每个片段必须保留源路径、页码或标题、时间戳和文档 ID。
3. 检索支持元数据过滤，并返回带分数的证据。
4. 回答结构必须包含 `answer`、`citations`、`confidence` 和 `refused`。
5. 短期会话状态按 `thread_id` 隔离。
6. 长期记忆按 `tenant_id` 和 `user_id` 隔离。
7. 记忆写入必须遵循明确策略，不能自动永久保存原始对话。

## 非功能需求

- 回答不得引用本次运行中没有检索到的片段。
- 文件更新后，旧版本片段不能继续保持活动状态。
- 本地语料库的响应时间目标：首次导入除外，P95 小于 8 秒。
- 模型和 Embedding 提供商必须可以通过适配器替换。
- 日志默认对文档内容和密钥进行脱敏。

## 第一版不包含的范围

- 自主网页浏览。
- 扫描版 PDF 的图像 OCR。
- 协作式文档编辑。
- 训练或微调 Embedding 模型。

## 主要风险

主要风险包括切分质量差、检索遗漏、相似度分数误导、引用漂移、上下文溢出、过期记忆和跨用户数据泄漏。
