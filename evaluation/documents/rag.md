# RAG 检索增强生成

RAG 的基础流程是加载文档、解析结构、切分片段、生成 Embedding、写入向量索引、根据问题检索证据，再把检索片段组织成模型上下文。切块过大可能混合多个主题，切块过小则可能丢失必要上下文，因此切块参数必须通过固定问题集评测。

知识助手生成回答时只能引用本次检索返回的 Chunk ID。确定性后置校验器需要检查回答中的每个引用是否确实存在于本轮 SearchResult 中，不能允许模型编造来源。检索结果通过文件名、页码、章节路径、Chunk ID 和分数保持可追溯性。

如果可靠证据不足，系统应明确拒答或者说明信息缺失，而不是依靠模型自报置信度继续猜测。证据不足策略属于回答层能力；纯 top-k 检索在没有分数阈值时通常仍会返回候选片段。
